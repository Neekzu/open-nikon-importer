# Auto-Update Plan

The intended update mechanism is Sparkle 2.

Sparkle should be enabled only after the public release pipeline is ready:

1. Apple Developer ID signing certificate is available.
2. App notarization works reliably.
3. Sparkle EdDSA keys are generated and the public key is embedded in `Info.plist`.
4. A GitHub Pages or website-hosted `appcast.xml` URL exists.
5. Release archives are generated by the packaging script and signed for Sparkle.
6. The app has a visible "Check for Updates" command.

Until those pieces are ready, the app should ship without runtime auto-update. A half-configured updater is worse than manual GitHub releases because updater security depends on signed archives and a trustworthy feed.

Target release flow:

```sh
./Scripts/package-app.sh
# sign/notarize with Developer ID
# sign archive with Sparkle
# generate appcast
# publish GitHub Release + appcast
```

Notes:

- Keep the Sparkle private key out of the repository.
- Keep `CFBundleVersion` incrementing on every public release.
- Prefer notarized Developer ID builds for public downloads.
